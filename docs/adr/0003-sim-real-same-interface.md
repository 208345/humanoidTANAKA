# ADR-0003: sim と実機を同一インターフェースの背後に隠す

- **日付**: 2026-08-09
- **状態**: 採用（**このプロジェクトで最も重要な決定**）

## 背景

シミュレーションと実機で制御コードをどう共有するか。

## 決定

`RobotInterface` という抽象クラスを定義し、`SimRobot` / `RealRobot` / `DummyRobot`
がそれを実装する。制御コードは相手が何であるかを知らない。
切り替えは起動時の引数のみ。

制御器についても同様に `Controller` 抽象を設け、
手設計の制御器と学習ポリシーを差し替え可能にする。

## 理由

- 実機は1台しかなく、3人が順番待ちになると開発速度が 1/3 になる。
  sim で作業できれば全員が常に前に進める
- sim 用と実機用のコードを分けると二重管理になり、必ず片方が腐る
- sim で歩けたポリシーをそのまま実機で試せることが sim-to-real の前提
- 手設計制御器と学習ポリシーを同じ実験スクリプトで比較できる

## 結果として起きること

- 抽象化のぶん、最初に書くコード量が少し増える
- 実機固有の機能（サーボ個別の設定など）は `extra` 経由の扱いになり、やや不格好
- **この境界を壊す変更は原則マージしない。** レビューの最優先確認項目とする
