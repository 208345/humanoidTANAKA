# learning — 強化学習による歩行ポリシーの獲得

## 方針

MuJoCo Playground（DeepMind、GPU 並列の MJX ベース）上で PPO により
速度指令追従の歩行ポリシーを学習し、実機へ zero-shot 転移することを目指す。

## 構成

| パス | 中身 |
|---|---|
| `envs/` | 環境定義。観測・行動・報酬・終了条件・ドメインランダム化 |
| `train/` | 学習スクリプトと設定ファイル |
| `policies/` | 学習済みの重み（Git には入れない） |
| `eval/` | 評価・可視化・sim-to-sim 検証 |

## 進め方（この順を守る）

1. **既存モデルで成功体験を作る** — MuJoCo Playground に含まれる小型ヒューマノイド
   （Robotis OP3 など）をまず歩かせる。自作モデルで最初に失敗すると原因が絞れない
2. 自作モデル（`model/humanoid.xml`）に差し替えて学習する
3. ドメインランダム化を入れる（質量・摩擦・サーボ遅延・IMU ノイズ・通信遅延）
4. `control/interface/controller.py` の `PolicyController` に載せて実機で評価する

## 最重要の注意

**学習時の観測の作り方と、実機での観測の作り方を完全に一致させること。**

正規化の係数、履歴の積み方、指令のスケール — どれか一つでもずれると転移しない。
そして、ずれていても sim では動いてしまうので気づけない。

これを防ぐため、観測を組み立てる関数は `envs/` と `PolicyController` で
**共有し、二重に書かない**。

## 教師あり学習の題材（RL と並行してできる。実機ログから作る）

- 接地判定の分類（IMU＋関節電流 → 足が着いているか）
- 転倒予測（数百ms先に転倒するかの二値分類）
- システム同定（応答データ → サーボの遅延・摩擦パラメータの推定）

3番目は**そのままドメインランダム化の設定値になる**ので、RL の精度に直結する。
地味に見えて、実は sim-to-real の成否を左右する部分。
